## 概要

对于系统级和模块级的校验，系统初始化需要一个注册码 （包含机器码、已激活功能、其他元信息、数字签名），系统会用保存在程序数据段的公钥去检查其中包含的功能，验证后将相关信息存入数据库。

当用户需要新的功能时候，厂商重新设置功能生成注册码，。由于很难做到撤回已经激活的功能（比如用户依旧保存旧的实例，在一台机器上多开）。所以这个流程设计默认功能卖出不能收回。

## 实现细节

- 机器码的获取并没有一个固定的渠道，一般来说使用 CPU ID、主板序列号、硬盘序列号 之类的信息做一个硬件指纹 Hash（其他的还可以用网卡 MAC、内存序列号等。但是由于获取难度以及稳定性，一般不作为主要参考）。
- 使用现代 Ed25519 作为签名算法可以有效减少签名长度 （RSA-2048 有 256 字节，Ed25519 是 64 字节 ）
- 为了提供灵活性，程序应当支持解析未来可能附加的元数据。但并不是必须项。设计上使用不定长（TLV, Type-Length-Value）设计。变长部分放在最后便于程序读取。

```bash
+-------------------------------+
| 8bytes 过期时间                |
+-------------------------------+
| 16bytes 开放功能位图            | 
+--------------------+----------+
| 1byte 硬件指纹长度   | 硬件指纹   |
+--------------------+----------+
| 2bytes 元数据 A 长度 | 元数据A   |
+-------------------+-----------+
｜            ......            |
+-------------------------------+
| 2 bytes 元数据 N 长度｜ 元数据 N |        
+-------------------+-----------+
| 64bytes 前面所有字节的签名       |
+-------------------------------+
```

上述机器码在没有额外元数据的情况，该结构原始二进制大小为 **121 字节**（24 字节数据 + 64 字节 ECC 签名 + 33 字节机器码），经过 Base64 编码之后将会是 164 个字符。大概效果如下：

```bash
SGVsbG8gdGhpcyBpcyBhIHNhbXBsZSBsaWNlbnNlIGNvZGUgZm9yIHlvdXIgYmFzZSBzeXN0ZW0uIEl0IGNvbnRhaW5zIG1hY2hpbmUgSUQsIGV4cGlyYXRpb24gdGltZSwgYW5kIDEyOC1iaXQgZmVhdHVyZSBtYXBzLg==
```

该结构可以满足当前离线 License 的数据承载需求，并为后续字段扩展预留空间。

##  注意事项

值得注意的是，如果攻击者拥有修改程序的能力，直接修改签名 hash 和字节码中的公钥，那么这个授权机制则会被绕过。

在生产领域，这个问题无法完美解决。但是可以提供额外的方法增加破解成本：

1. 使用开源的 `mainline/garble` 工具对 Go 二进制进行混淆，擦除反射信息和字符串，让黑客用 IDA Pro 逆向时找不到 `VerifyLicense` 或 `publicKey` 这种明显的关键字。
2. 将 License 拆分，散落在程序的不同位置，程序运行时拼接使用。
3. 在程序执行的多个位置进行随机 License 校验，而不是只在启动时进行校验
